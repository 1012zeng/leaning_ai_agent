先抓主干

1. 一个心智模型：先通信，再计算

一个 Transformer block 反复做两件事：Attention 让 token 之间交换信息，FFN 让每个 token 独立加工刚拿到的信息。

一句话定义 Transformer 是一种批量处理 token 的神经网络架构：它用注意力选择上下文，用前馈网络变换特征，再用残差连接把很多层稳定地叠起来。
组件白话问题做的事不做的事
Embedding这个 token 是谁？ID 查表得到向量不知道上下文
Position它排在第几位？注入顺序信息不判断语义
Attention此刻该向谁取信息？跨 token 加权聚合不负责复杂的逐点变换
FFN拿到信息后怎么算？每个位置独立做非线性变换不与别的位置通信
Residual + Norm怎样叠深而不失控？保留原信号并稳定数值不是语义模块
先不要把 Q、K、V 当三个神秘新对象 它们通常都来自同一批 token 向量，只是分别乘了不同的可学习矩阵，于是承担“发起查询、被匹配、提供内容”三种角色。

全局地图

2. 跟踪“帮我检查这段代码”

先看 decoder-only 模型的一次前向传播。现代文本生成模型大多走这条主线；第 9 章再对比 encoder 和 encoder-decoder。

  1. 文本“帮我检查这段代码”
  2. Token IDs[41, 92, 307, ...]
  3. 向量 + 位置(B, T, D)
  4. N 个 BlockAttention + FFN
  5. Logits(B, T, V)
  6. 下一个 Tokensoftmax + 选择

逐步发生了什么

  1. Tokenizer 把字符串切成 token，并映射为整数 ID。Tokenizer 是规则/算法，不是 Transformer block。
  2. Embedding 用 ID 查表。若词表大小为 V，隐藏维为 D，嵌入表形状是 (V, D)。
  3. 位置信息 与 token 表示结合，使“代码检查”和“检查代码”不再只是同一堆向量。
  4. N 个 block 反复建立上下文。越往后，每个 token 的向量越不是“词典释义”，而是当前句子中的语境表示。
  5. 输出投影 把每个位置的 D 维表示投影到词表大小 V，得到 logits。
  6. 解码策略 把最后一个位置的 logits 变成概率，选择一个新 token，再把它接回输入继续生成。
常见混淆 “Transformer 输出一句话”是应用层说法。单次前向传播输出的是各位置对词表的分数；完整句子来自多次前向传播组成的自回归循环。

工程抓手

3. 张量形状比公式更先学

后续统一使用一个不太玩具化的例子：批量 B=2，序列长度 T=6，模型维度 D=8，头数 H=2，每头维度 D_head=4。

符号含义本例代码中常见形状
Bbatch size，一次几条样本2第 0 维
T序列 token 数6第 1 或倒数第 2 维
D每个 token 的隐藏维8最后一维
H注意力头数2切头后第 1 维
D_head每个头的维度4D / H
V词表大小例如 50,000logits 最后一维
X (2, 6, 8) ├─ 乘 Wq/Wk/Wv (8, 8) ▼ Q, K, V (2, 6, 8) ├─ reshape + transpose ▼ Q, K, V 多头 (2, 2, 6, 4) ├─ Q @ K^T ▼ attention scores (2, 2, 6, 6) ├─ softmax 后 @ V ▼ 每头输出 (2, 2, 6, 4) ├─ transpose + reshape ▼ 合并输出 (2, 6, 8)
形状自测 若 B=4, T=10, D=512, H=8，请口算 scores 的形状。答案是 (4, 8, 10, 10)，不是 (4, 10, 512)。

核心机制

4. Attention：按当前需要检索上下文

直观上它像一次内存检索：Query 表示“我现在要找什么”，Key 表示“我能被怎样匹配”，Value 表示“匹配上以后我提供什么内容”。

Attention(Q, K, V) = softmax((Q @ K^T) / sqrt(D_head) + Mask) @ V

4.1 五步拆开

  1. X @ Wq 得到 Query，X @ Wk 得到 Key，X @ Wv 得到 Value。
  2. Q @ K^T 让每个 Query 与所有 Key 做点积，得到匹配分数。
  3. 除以 sqrt(D_head)，避免维度大时分数方差过大，softmax 过早接近 0/1。
  4. 加入 Mask，把不允许看的位置变成极小值。
  5. softmax 得到权重，再乘 Value，形成上下文加权和。

4.2 一个可核算的四 token 例子

我们人为设计一个二维查询。它只用于观察计算，不代表模型已经学会语义：

tokens = ["写", "代码", "查", "文档"]
Q = [[1.0, 0.0]]
K = [[0.2, 0.8],
     [0.9, 0.1],
     [0.1, 0.9],
     [0.8, 0.2]]
V = [[1.0, 0.0],
     [0.0, 2.0],
     [3.0, 0.0],
     [0.0, 4.0]]
被关注 tokenQ·K除以 sqrt(2)softmax 权重
写0.200.1410.196
代码0.900.6360.322
查0.100.0710.183
文档0.800.5660.300

softmax 之后，“代码”和“文档”权重更大。最终输出不是选中某一个 Value，而是四个 Value 的加权和。第 11.1 节会用代码打印精确结果。

4.3 注意力矩阵如何读

行是发起查询的 token，列是被读取的 token。选择一行观察权重：

Query我查代码文档
我0.500.100.200.20

“我”保留较多自身信息，同时读取任务对象。这里的数字是教学示意，不是从真实模型抽取。

纠错：单位矩阵经过 softmax 不会变成均匀权重 对一行 [1, 0] 做 softmax，结果约为 [0.731, 0.269]；若先除以 sqrt(2)，约为 [0.670, 0.330]。只有输入分数相同，softmax 才均匀。
进一步理解：为什么除以 sqrt(D_head)

若 Q 和 K 的各分量近似独立、均值为 0、方差为 1，点积是 D_head 项乘积之和，方差约随 D_head 增长。除以平方根后，分数尺度重新回到较稳定范围。

这不是为了让结果“更小更好”，而是为了避免 softmax 落入过度尖锐、梯度很小的区域。

并行视角

5. 多头：在多个子空间并行检索

多头不是把同一份注意力复制 H 次，而是把 D 维表示投影、拆成 H 份，每份在自己的 D_head 维空间计算注意力。

D_head = D / H　　head_i = Attention(Q_i, K_i, V_i)　　MHA = Concat(head_1 ... head_H) @ Wo

在本例中，D=8, H=2，所以每头 D_head=4：

# (B, T, D) -> (B, T, H, D_head) -> (B, H, T, D_head)
x = x.reshape(batch_size, seq_len, n_heads, d_head)
x = x.transpose(0, 2, 1, 3)

为什么 reshape 后还要 transpose？

reshape 只重新解释内存布局，得到 (B, T, H, D_head)；注意力希望每个 batch、每个 head 各自处理完整序列，因此要把 head 移到 token 前面，变为 (B, H, T, D_head)。

“不同头一定学语法、指代、位置”只是帮助入门的类比 训练后某些头会呈现可辨认模式，但头的分工不是人为指定，也不保证每个头都有单一、稳定、可解释的职责。
改错题 有人把 (2, 6, 8) 直接 reshape 成 (2, 2, 6, 4)。元素总数虽然相同，但 token 与 head 的元素顺序错了。正确做法是先 (2, 6, 2, 4)，再 transpose。

顺序信息

6. 没有位置，注意力只看见“一袋 token”

自注意力本身不会因为 token 出现在第 1 位还是第 5 位而自动改变规则，所以必须注入位置信息。

6.1 原论文正弦位置编码

PE(pos, 2i) = sin(pos / 10000^(2i/D))　　PE(pos, 2i+1) = cos(pos / 10000^(2i/D))

每一对偶数/奇数维使用同一个频率，一个取 sin，一个取 cos。位置 0 的偶数维全为 0，奇数维全为 1，这是非常好用的测试性质。

positions = np.arange(seq_len)[:, None]
frequencies = np.exp(
    -np.log(10000.0) * np.arange(0, d_model, 2) / d_model
)
angles = positions * frequencies[None, :]

pe = np.zeros((seq_len, d_model))
pe[:, 0::2] = np.sin(angles)
pe[:, 1::2] = np.cos(angles)
高频实现错误 不能让奇数维单独使用新的频率。维度 0/1 是一对，2/3 是一对；每对必须共用同一个 angle，才能满足 sin²(angle) + cos²(angle) = 1。

6.2 现代模型常见方式

方式核心想法需要记住
固定正弦编码把位置向量加到 token embedding无可学习参数，适合教学公式
可学习绝对位置位置也查一张 embedding 表简单灵活，长度受训练表限制
RoPE按位置旋转 Q/K，使点积带上相对位置信息现代 decoder-only 常见；超长外推通常还需缩放策略
ALiBi按相对距离给注意力分数加线性偏置不直接修改 token embedding

可见性规则

7. Mask：规定哪些位置有读取权限

Mask 不是删除 token，而是在 softmax 前把禁止位置的分数设为极小值，使其权重变成 0。

7.1 Causal mask：不能偷看未来

长度为 4 时，True 表示允许关注：

[[1, 0, 0, 0],
 [1, 1, 0, 0],
 [1, 1, 1, 0],
 [1, 1, 1, 1]]

第 2 行只能看位置 0、1、2，不能看位置 3。训练时目标 token 都在输入里，causal mask 防止模型直接看到答案。

7.2 Padding mask：不要读取补齐位

一个 batch 中句子长度不同，短句会补 PAD。若两条样本有效长度是 [5, 3]，第二条样本的 key 位置 3、4 必须被屏蔽。

7.3 广播后的形状

对象形状作用
scores(B, H, T, T)每个样本、每个头、每个 query 对每个 key 的分数
causal mask(1, 1, T, T)对所有 batch 和 head 使用同一时间规则
padding mask(B, 1, 1, T)每个样本有不同有效 key 长度
组合 mask广播到 (B, 1, T, T)同时禁止未来和 PAD
团队项目必须约定 Mask 语义 有的库用 True 表示“保留”，有的用 True 表示“屏蔽”。本教案统一使用 True = 允许关注，并把参数命名为 allowed_mask，避免只写含糊的 mask。

组装一层

8. Transformer Block：通信、加工、保真

理解了 attention 仍只完成一半。真正能叠几十层甚至更多层，依赖 FFN、残差和归一化的配合。

8.1 Pre-LN decoder block

Y = X + MaskedMHA(LN(X))　　Output = Y + FFN(LN(Y))
X ── LayerNorm ── Masked Multi-Head Attention ──┐ │ │ └──────────────────────── residual add ──────────┘ = Y Y ── LayerNorm ── Linear(D→D_ff) ── activation ── Linear(D_ff→D) ──┐ │ │ └────────────────────────── residual add ───────────────────────────┘ = Output

8.2 FFN 到底做什么

FFN(x) = activation(x @ W1 + b1) @ W2 + b2

Attention 的输出是其他 token 信息的混合；FFN 对每个位置独立使用同一套参数，把这些信息进行非线性组合。若 D=8, D_ff=16：

  • W1 形状 (8, 16)，先扩维；
  • 激活函数引入非线性；
  • W2 形状 (16, 8)，再回到残差可相加的维度。

8.3 残差连接为什么要求形状不变

X + sublayer(X) 是逐元素相加，所以子层输出必须回到 (B, T, D)。残差提供一条直接的信息和梯度通路，子层只需学习相对输入的改变量。

8.4 LayerNorm 在归一化什么

对每个 token 的 D 个特征分别计算均值和方差。输入 (B, T, D) 时，代码通常使用 axis=-1；它不跨 batch 聚合统计量。

原论文与现代实现要分开说 2017 原论文结构常称 Post-LN：子层后做残差和 LayerNorm。许多现代大模型使用 Pre-LN 或其变体以改善深层训练稳定性。本教案实战采用更容易追踪的 Pre-LN，但面试时要能说明两者区别。

架构选择

9. Encoder、Decoder-only、Encoder-Decoder

“Transformer 架构”不是唯一一种固定堆法。任务需要怎样的信息流，决定保留哪些模块。

Decoder-only：只看左侧上下文，逐 token 生成

每层使用 causal self-attention，没有标准 encoder-decoder cross-attention。典型任务是续写、对话、代码生成。GPT 风格大语言模型属于这一类。

架构注意力可见范围典型目标代表性用途
Encoder-only双向看到整段输入得到上下文表示或分类结果文本分类、检索编码、实体识别
Decoder-only因果单向，只看当前位置及之前预测下一个 token通用生成式大模型
Encoder-Decoderencoder 双向；decoder 因果；另有 cross-attention根据源序列生成目标序列翻译、摘要、受控生成

Cross-Attention 的来源不同

自注意力中 Q/K/V 来自同一序列。Encoder-Decoder 的 cross-attention 中，Q 来自 decoder 当前状态，K/V 来自 encoder 输出。这相当于“边写译文，边回看原文”。

模型如何学与写

10. 训练并行，生成串行

同一个 decoder-only block 在训练和推理时参数相同，数据供给方式不同。

10.1 训练：右移目标 + 交叉熵

假设文本 token 是 [BOS, 我, 写, 代码, EOS]：

输入位置模型应该预测
BOS我
我写
写代码
代码EOS

所有目标都已知，因此可一次算出所有位置的 logits；causal mask 保证每个位置没偷看右侧答案。交叉熵只取真实下一个 token 的负对数概率：

loss = -mean(log P(真实下一个 token | 左侧上下文))

10.2 推理：循环调用前向传播

tokens = [BOS]
while len(tokens) < max_length:
    logits = model(tokens)
    next_token = choose(logits[-1], temperature, top_p)
    tokens.append(next_token)
    if next_token == EOS:
        break

10.3 Temperature 改变分布，不改变知识

使用 softmax(logits / T)。T < 1 让分布更尖锐，输出更确定；T > 1 让分布更平，随机性更高。它不会让模型突然知道训练中没学到的事实。

10.4 KV cache 到底省了什么

生成新 token 时，历史 token 的 K/V 不会改变，可以缓存。这样每一步只计算新 token 的 Q/K/V，再让新 Query 读取历史 Key/Value，避免反复重算整个前缀。标准全注意力在序列不断增长时仍需读取越来越长的缓存；KV cache 降低重复计算，不会让长上下文成本消失。

13.3 改错题

scores = q @ k.transpose(0, 1, 3, 2)
weights = np.exp(scores) / np.exp(scores).sum(axis=1, keepdims=True)
output = weights @ v

至少指出两处问题：缺少 sqrt(D_head) 缩放；softmax 轴应是最后一维而不是 head 维；直接 exp 还缺少减最大值的数值稳定处理；decoder 场景还缺 causal mask。
