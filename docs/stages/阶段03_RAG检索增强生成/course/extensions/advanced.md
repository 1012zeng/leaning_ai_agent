# A01-A04：前沿选修入口

这些内容用于拓展边界，不计入必修 G1-G4，也不能替代朴素 RAG、检索评测、引用和生产恢复。先交付可测试的单 pipeline，再判断复杂架构是否解决真实瓶颈。

## 选修准入

只有同时满足以下条件才开始：

1. 已完成 L01-L06 和 E01-E04。
2. 有一个固定评测集和明确失败切片，能证明当前单 pipeline 的瓶颈。
3. 复杂方案有对照组、成本预算、停止条件和回退路径。
4. 新对象/事件通过 adapter 或已批准契约扩展，不破坏既有对象链。

## A01：GraphRAG

适用信号：问题依赖多跳实体关系、全局群落/主题摘要，普通 chunk 检索在相关边上持续漏召回。学习重点：图 schema、实体/关系 provenance、图构建质量、局部/全局检索、图与向量融合、增量更新和评测。

最低实验：与 hybrid baseline 在同一多跳切片比较 Recall/nDCG、answer correctness、构图成本、查询 p95 和更新复杂度。若只在展示图上更漂亮而质量/成本无证据，不采用。

## A02：Agentic RAG

适用信号：问题需要多步查询规划、按中间结果选择工具或向用户澄清，确定性 query decomposition 无法覆盖。学习重点：tool schema、状态、终止条件、预算、权限、人工确认、失败恢复和 trace。

最低实验：先与确定性 workflow 比较成功率、工具调用正确率、步骤数、成本和不可恢复失败。单 Agent 能解决时不引入多 Agent；检索本身可一次完成时不引入 Agent。

## A03：多模态 RAG

适用信号：答案证据存在图表、版面、图像或音视频中，纯文本解析持续丢失关键关系。学习重点：模态专属 parser、跨模态 identity/span、query/document 编码、late interaction、引用渲染、版权与隐私。

最低实验：为文本-only 与多模态方案建立同一事实层的评测标签，比较证据召回、引用正确、延迟、显存和存储。OCR 文本变好不代表图表关系已正确理解。

## A04：部署与成本深化

适用信号：离线工程满足质量门槛后，需要服务化、缓存、流式、队列、弹性或多租户。学习重点：同步/异步 API、SSE、背压、cache invalidation、容量模型、SLO、灰度与回滚。

最低实验：用真实业务 canary 验证检索、生成和引用，不以端口可连或 HTTP 200 作为成功；给出容量、p95/p99、错误预算、单位 query 成本和降级策略。

## 选修交付模板

每个选修提交一页决策记录：当前瓶颈证据、对照方案、增加的对象/模块、实验设计、质量/延迟/成本结果、安全与恢复影响、采用/拒绝结论。没有指标改善也可以是高质量结论，但必须可复现。

下一步：从当前综合项目的失败切片中选一个问题；若没有清楚瓶颈，停止选修并继续完善主线证据。
